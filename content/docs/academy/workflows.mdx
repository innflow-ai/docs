<LearningGoals>
- Recognize triggers, nodes, and connections.
- Test a workflow and inspect the output before deploying it.
</LearningGoals>

## Choose a clear outcome

A good first workflow answers a small question or transforms a sample input. Avoid starting with an automation that writes to several production systems.

<Steps>
<Step title="Create a workflow">Open Workflows and create a new workflow. Give it a name that describes its outcome.</Step>
<Step title="Add a starting point">Use a Manual trigger for an initial test. Connect an action node and complete its required fields.</Step>
<Step title="Run with sample data">Run the workflow from the editor. Open the execution details and inspect the node output.</Step>
<Step title="Connect the next action">Use the variable picker to pass the first node's result to the next node. Run it again and inspect both steps.</Step>
</Steps>

## Connections describe execution

A connection tells the workflow which node can run next. The output of a completed node becomes available to downstream steps. A branch or loop changes the path, so test each path your process depends on.

## Arrange and save

Follow the canvas from left to right, connecting an output on the right of one node to an input on the left of the next. Branch labels identify the path; visual position alone does not determine execution.

Before closing the editor, check that the toolbar reports **All changes saved**. Changes made during an earlier save may still need another save. If a conflict appears, preserve your work and reconcile it with the latest workflow before reloading. See [saving and conflicts](/essentials/workflows#saving-and-conflicts).

## Try it

Build a Manual trigger connected to an AI node. Ask it to summarize a short sample message. Check whether the actual output matches what the next step needs before connecting an email or messaging action.
