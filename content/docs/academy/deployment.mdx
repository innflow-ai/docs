## Choose how work arrives

A Manual trigger is useful for testing. A webhook can receive an event from another system, a schedule can start recurring work, and a form can collect structured input. Use the trigger reference to check configuration for your chosen entry point.

## Review before deployment

Check required fields, selected credentials, branch destinations, and sample outputs. Confirm that any messages or writes go to the intended destination. Deploy the workflow when the test matches the process you want to automate.

## Trigger availability

Add additional triggers directly. Existing drafts switch to independent execution when the second trigger saves; no separate enablement setting is needed. Undeploy and drain active or pending runs before changing entry points. See [adding another trigger](/triggers#adding-another-trigger), then test every intended entry point before redeploying.

## Try it

Deploy a small test workflow with your selected trigger, send one controlled event, and verify the resulting execution. If the trigger does not start a run, check deployment state and the trigger's own setup.
