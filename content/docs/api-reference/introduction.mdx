## Overview

The Innflow public API manages workspaces, workflow definitions, deployment state, and executions. It is also the API used by the [Innflow CLI](/api-reference/cli).

## Authentication

All API requests require an API key in the `Authorization` header. Innflow API keys start with `inf_sk_` and are shown only once when created.

```bash
curl -H "Authorization: Bearer inf_sk_..." \
  https://app.innflow.ai/api/v1/workflows
```

## Base URL

```
https://app.innflow.ai/api/v1
```

The machine-readable OpenAPI 3.1 document is available at:

```txt
https://app.innflow.ai/api/v1/openapi.json
```

## Workspace selection

Requests default to the personal workspace. Pass an organization ID in `X-Innflow-Workspace` to operate in another accessible workspace:

```bash
-H "X-Innflow-Workspace: org_123"
```

Read-only workspace members cannot use write endpoints.

## Idempotent writes

Create, import, duplicate, deploy, undeploy, and execute requests support an `Idempotency-Key` header. Repeating the same request with the same key replays the saved response for 24 hours; reusing a key with a different request returns a conflict.

## Endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/workspaces` | List accessible workspaces |
| `GET`, `POST` | `/workflows` | List or create workflows |
| `POST` | `/workflows/import` | Import a workflow graph |
| `GET`, `PATCH`, `DELETE` | `/workflows/{workflowId}` | Read, update, or delete one workflow |
| `POST` | `/workflows/{workflowId}/duplicate` | Duplicate a workflow |
| `POST` | `/workflows/{workflowId}/deploy` | Deploy a workflow |
| `POST` | `/workflows/{workflowId}/undeploy` | Return a workflow to draft state |
| `POST` | `/workflows/{workflowId}/execute` | Start a deployed workflow |
| `GET` | `/executions` | List executions |
| `GET` | `/executions/{executionId}` | Read execution details and node logs |

## Workflow layout metadata

Workflow definitions can carry `canvasLayoutVersion` alongside their nodes and connections. Version `0` identifies a definition eligible for the editor's one-time horizontal arrangement; version `1` identifies one already using that layout version. Imports without the field default to `0`, while newly created workflows start at `1`. Duplicating a workflow preserves its value.

Preserve this field when exporting and reimporting a definition. It tracks canvas arrangement separately from execution version or deployment state; importing an older definition does not rearrange it until it is opened in an editable editor. Use the current OpenAPI schema for endpoint-specific input fields.

## Execute a Workflow

Workflows must be deployed before they can be executed through the API.

```bash
curl -X POST https://app.innflow.ai/api/v1/workflows/{workflowId}/execute \
  -H "Authorization: Bearer inf_sk_..." \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: run-customer-onboarding-123" \
  -d '{
    "input": {
      "email": "customer@example.com",
      "message": "Need help with onboarding"
    }
  }'
```

The response includes the workflow ID, event IDs, and a `triggered` status.

## Errors and request IDs

JSON errors include a human-readable `error`, an optional machine-readable `code`, and a `requestId`. Responses also include `X-Request-Id`; provide it to support when investigating a failed request.
