Use the Innflow REST API to create and import workflows, deploy them, start executions and read results. The API also exposes graph authoring, node schemas and connected-account discovery.

**Base URL**

```text
https://app.innflow.ai/api/v1
```

[Browse all 25 operations](/api-reference/endpoints) · [Download OpenAPI 3.1](/openapi.json) · [CLI reference](/api-reference/cli)

## Make your first request

Create a key in **Settings → API Keys**. The full key is shown once. Store it on your server or in your shell environment as `INNFLOW_API_KEY`.

```bash
curl 'https://app.innflow.ai/api/v1/workspaces' \
  --header "Authorization: Bearer $INNFLOW_API_KEY"
```

List workflows in your personal workspace (select it explicitly):

```bash
curl 'https://app.innflow.ai/api/v1/workflows?page=1&pageSize=20' \
  --header 'X-Innflow-Workspace: personal' \
  --header "Authorization: Bearer $INNFLOW_API_KEY"
```

To select an organization, add `X-Innflow-Workspace` with an organization ID returned by List workspaces. See [authentication, permissions and errors](/api-reference/authentication).

## Start a workflow and read its result

Choose a configured, deployed workflow. Replace `workflow_id` with its ID. Give each new execution a unique idempotency key; reuse that key only when retrying the same request.

```bash
curl --request POST 'https://app.innflow.ai/api/v1/workflows/workflow_id/execute' \
  --header "Authorization: Bearer $INNFLOW_API_KEY" \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: customer-onboarding-001' \
  --data '{"input":{"email":"customer@example.com"}}'
```

The response's `data.executionId` identifies the asynchronous run. If several triggers are eligible, include `triggerNodeId` in the request body.

```bash
curl 'https://app.innflow.ai/api/v1/executions/execution_id?view=summary' \
  --header "Authorization: Bearer $INNFLOW_API_KEY"
```

Poll with backoff until the execution finishes. Use [execution logs](/api-reference/endpoints/execution-logs) for node-level diagnostics and [execution payload](/api-reference/endpoints/execution-payload) for chunked output.

## Supported surface

These pages describe the customer REST routes under `/api/v1`. Authoring availability is deployment-dependent; check [authoring context](/api-reference/endpoints/authoring-context) before editing graphs. Workflow webhooks and [MCP](/mcp) have their own setup guides. Internal service endpoints and browser-session APIs are not customer REST contracts.

## Workflow layout metadata

Workflow definitions can carry `canvasLayoutVersion` alongside nodes and connections. Version `0` identifies a definition eligible for the editor’s one-time horizontal arrangement; version `1` identifies one already using that layout version. Imports default to `0`, new workflows start at `1`, and duplicates preserve the value. Preserve this field across exports and imports. It tracks canvas arrangement separately from execution version or deployment state.
